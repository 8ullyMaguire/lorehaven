# Lorehaven — from-scratch revision (2026-10-04)

Read: docs/goal.md, spec.md (10725 lines), requirements.csv
(683 rows: 611 implemented / 60 planned / 4 unsupported),
remaining-work.md, 91 migrations × 2 dialects, 118 test files.

The process is the best in the estate (CSV as canonical inventory,
ADR-numbered decisions, dual-dialect parity tests). The spec is the
problem.

1. **10,725 lines is not a spec, it's an archive.** From scratch:
   spec.md is the product (goals, primitives, data model, the 10
   load-bearing decisions) at ≤1500 lines; requirements.csv remains
   the inventory; ADRs remain the decision log. The current file
   mixes all three, so "what is the product" is unanswerable in
   one read. The CSV + remaining-work.md already prove the
   machinery works without the monolith.
2. **Verification debt is the real backlog, not the 60 planned
   rows.** 206 "locally tested" + 116 E2E-verified means ~half the
   implemented surface has no end-to-end proof. From scratch, the
   definition of "implemented" requires the E2E grade, and the
   CSV's three grades collapse to two (tested / verified). A
   feature that works but was never verified is a bug with
   unknown location.
3. **The M59 crawling/retention amendment pattern is right**
   (amendment doc + plan + evidence). Adopt it as THE extension
   mechanism and retire inline spec edits: an amendment is a
   versioned doc that spec.md references, so the spec's history
   is readable.
4. **spec.md.bak in docs/ is a hazard.** From scratch: deleted
   specs live in git; a .bak next to the live file is a stale-copy
   trap (the gravity threadlight lesson: hand-maintained copies
   diverge invisibly).
5. **Federation:** docs/ has federation-status.md and a session
   summary but the consolidated spec's federation section is
   buried. From scratch, federation gets its own top-level doc
   (like gravity's §19 should have) — it's the highest-risk
   surface and the least readable at depth.

## Verdict
The build discipline (CSV, ADRs, parity tests) is what gravity
should copy. The spec monolith is what to dismantle: product doc,
inventory, and decision log are three files, not one 10k-line file.
