## Milestone 3 record

The session that produced Milestone 3 also fixed two bugs that had been open
since the first milestone run. The record of those fixes is kept here so the
reader can see how the investigation proceeded and what the fixes actually were.

### The two bugs, found

Both were discovered while driving the acceptance tests for Milestone 3
(`cargo test --package lorehaven-app --test milestone_3`) after the
first full suite run. The two tests that failed were:

1. **`switching_pseud_shows_a_different_history`** — `500` was returned where
   the test expects `200`. The cause was a bind-count mismatch in
   `history_for`'s SQL: the query has three placeholders (`account_id`,
   `pseud_id`, `limit`) and both call sites bound two, so `pseud_id` was
   never sent and `limit` was bound into its position. The missing
   `.bind(pseud.to_string())` was added to both dialect arms. The route
   now answers `200`.
2. **`clearing_history_removes_only_the_callers_rows`** — the test registered
   the handles `"A"` and `"B"`, which the identity rules refuse (three
   characters minimum), so it was asserting about a registration that had
   never happened. Renamed to `AAA` and `BBB`. Passes.

### What is still true from the earlier record

Both decisions the earlier summary said should not be re-litigated still hold
and were not revisited: history is per pseud and `history_for` takes a
`PseudId`; and position is stored as `position_permille`, not a `REAL`, so the
crate's bind-only-`String`-and-`i64` rule survives. The reader is still not
behind a session, and it still reaches content through `can_access_content`
rather than growing an eligibility check of its own.
