## Session 1 — Milestone 4: the backend and pages

The milestone's backend and pages existed but did not work end to end. Six
defects, none of them found by reading:

1. **`list_reviews` and `upsert_review` were stubs.** A `PUT` to create a review
   reported success and stored nothing; the `GET` returned an empty array
   whatever the database held.
2. **The review route was registered `post(...)` and the frontend sent `PUT`.**
   `405` for every review the interface would ever have sent.
3. **`/library/history` resolved to `history` in the router and `App.svelte` had
   no branch for it**, so the route fell through to `NotFound`.
4. **Three pairs of duplicate pages existed** — `ChapterRead`/`Reader`,
   `WorkRead`/`WorkPage`, `TypographySettings`/`ReaderSettings`. The shell
   rendered the older, emptier one of each pair, so position tracking, ratings,

   code): the reader had no way to see the public aggregate, because the type
   existed and no route returned it. It is now served on the public work view.
6. **`frontend/src/lib/reading.test.ts` leaked a `localStorage` spy between
   tests**, which is why the suite was green by ordering rather than by passing.

## Session 2 — Milestone 4 closed and tagged

### What was done

Session 1 left Milestone 4 with three unsettled criteria and no tag. This session
settled them, and then drove the reader in a browser, which found eight defects
the acceptance tests could not see.

**The three criteria.** `M4-11` (private notes) is closed by three acceptance
tests and a repository fix. `M4-12` (search within a work) and `M4-13`
(whole-work mode) were re-scoped, with the operator's agreement, to Milestone 9
(which builds the index a search needs) and Milestone 8 (the reader's library)
— tracked as `M9-02` and `M8-02`, with the reasoning in
`docs/requirements.csv`, `docs/plans/milestone-04-reader.md` and
`docs/verification.md`.

**The defects fixed**, each with the test that now pins it (details and
evidence in `docs/verification.md`):

1. `save_note` appended a second note on every edit — `ON CONFLICT DO UPDATE`
   against a key the schema has no unique index for. The upsert is written out
   in one transaction.
2. The two new note tests asserted nothing: their URLs contained a literal
   `{work_id}` rather than being interpolated, so they queried a subject that
   does not exist.
3. The pre-paint typography script was inline and therefore refused by
   `Content-Security-Policy: script-src 'self'`, silently. It is
   `frontend/static/prepaint.js` now, and a test fails if an inline script
   returns to the shell.
4. `applyTypography` wrote `data-reader-theme`; `tokens.css` selects
   `[data-reader='…']`. The reader's theme control changed no pixel. The reader
   now has its own four presets (paper, white, sepia, dark) and an unknown
   stored value resolves to the default.
5. `distraction_free` was written to the document and read by nothing; the
   checkbox now hides the shell's chrome.
6. `touch_history` had no caller in the application, so `/library/history` was
   empty for every real reader while the acceptance tests — which called the
   repository directly — stayed green.
7. The reader never wrote the local position cache, so "a lost request still
   leaves a position" was false, and a signed-out reader's position was kept
   nowhere.
8. Arriving in a chapter was not recorded as a reading; the position was only
   reported on scroll.

## Session 3 — Milestone 5: jobs, storage, secret encryption and the worker

Spec §10. Tag `v0.06-jobs`. The milestone's own record is
`docs/plans/milestone-05-jobs.md`; the evidence is in `docs/verification.md`.

### What was built

* **Migration 0005** in both dialects — `jobs`, `job_attempts`, `content_blobs`,
  `content_references`, `encryption_keys`, `secrets`.
* **`crates/domain/src/jobs.rs`** — the state machine, `RetryPolicy`, and a pure
  `next_attempt_at` whose jitter is a hash of the job id, so a retry's scheduled
  time is reproducible in a test.
* **`crates/db/src/jobs.rs`** — enqueue, claim (one statement), heartbeat,
  complete, fail, cancel, progress, requeue-on-expiry, the two paginated lists,
  and the sweep.
* **`crates/db/src/storage.rs`** — SHA-256 content addressing, temporary file
  plus rename, and `delete_if_unreferenced` as the only deletion path.
* **`crates/app/src/secrets.rs`** — XChaCha20-Poly1305 with the row bound in as
  associated data, and a `Debug` that prints `<secret>`.
* **`crates/app/src/worker.rs`** — the claim/run/record loop, graceful shutdown,
  and the outbox drain that finally reads what Milestone 3 has been writing.
* **Routes and pages** — `/jobs` and `/admin/jobs`, the operator gate on
  `config.administration.operator_account_id` (404, never 403), and a
  development-only `POST /jobs` so the journey is drivable before M6.
* **`lorehaven doctor`** — a `secret-key` check that loads the key and
  round-trips a value through it, so an instance that cannot encrypt says so at
  diagnosis time rather than when a reader first stores a credential.

### What the journey found, that reading did not

1. **A hex secret key was rejected as "48 bytes".** A 64-character hex key is
   also valid base64, so whichever decoder ran first decided the answer.
   `SecretKey::parse` now takes the reading that is a 32-byte key.
2. **`attempts` read `0` for a job that had run.** Only `fail` incremented it, so
   a first-try success claimed *0 of 5* while `job_attempts` held a row proving
   otherwise. `attempt_started` records the attempt now, and the retry decision
   reads that number back rather than adding one — which also stops an attempt
   being counted twice.
3. **The embedded bundle was stale.** `/jobs` answered "no such page" because the
   frontend build had not been re-run before the binary was built; `build.rs`
   embeds `frontend/dist` at compile time. Worth remembering: a new page is not
   visible until both `fe.sh build` and `cargo build` have run.

Three of the secrets tests were failing on a fixture bug rather than a code bug:
every test key was constructed with the same `key_id`, so the "retired key" and
"unknown key" tests were both exercising a rotation where the new key claimed the
old key's identity. The fixture now derives the id from the material, which is
what a real rotation produces.

A note on method, because it is the third milestone in a row to prove it: the
acceptance tests were green before the browser was opened, and the two real
defects were found in the browser. The API-level tests cannot see a counter that
reads zero on a page nobody rendered.

### Deliberately not done, and said so

`job_leases` as a table (the lease is two columns on `jobs`); the source revision
cache (nothing populates it before M6); quota *enforcement* (M7's export limits,
M17's storage view); and a caller for the encrypted-secret store (M6 stores source
credentials in it — tracked as `M5-03`). Each is recorded in
`docs/plans/milestone-05-jobs.md` rather than left as a silent gap.

Two more corrections to the plan, recorded in the same place: `POST /jobs` was
added as a development-only route because the plan's route list gave no way to
start a job before M6, and the `probe` maintenance job grew a `{"fail": "…"}`
switch so the retry path could be tested and rehearsed.
