## What was built in this session

### Milestone 0 — the running application

Three-crate workspace (`domain` / `db` / `app`), dual-dialect migrations
embedded in the binary, layered configuration, structured logging with request
IDs, health endpoints that distinguish liveness from readiness, an idempotent
development seeder, `doctor`, and a Svelte frontend embedded in the executable.

### Milestone 1 — design system and navigation

"The Reading Room" tokens (warm paper, evergreen, copper) with three presets
plus system preference; fifteen accessible components; the navigation shell with
desktop and mobile layouts.

### Milestone 2 — accounts, pseuds, privacy, age policy

**Schema.** Migration `0002` adds `sessions.active_pseud_id` (session-scoped, so
one device cannot switch another's face) and `content_settings`.

**Sessions and CSRF.** Opaque tokens stored only as SHA-256 hashes; `HttpOnly`
session cookie plus a readable CSRF cookie whose hash is on the session row, so
a cross-site attacker cannot produce the matching header. Cookie parsing and
writing are hand-written so the rules are readable in one place.

**Rate limiting.** Token buckets, per address *and* per account, keyed by route
class (`auth` / `write` / `search` / `default`), with pruning so the bucket map
is not a slow leak.

**Endpoints.** `register`, `login`, `logout`, `password-reset`,
`password-reset/complete`, `sessions` (list, revoke one, revoke all), `me`;
pseuds (list, create, edit, activate, public profile); privacy and content
settings.

**Design decisions worth remembering**

* Account-scoped and pseud-scoped privacy keys are declared once, with a
  `Scope` on each key, so a key cannot mean two different things depending on
  which endpoint wrote it.
* A self-declared adult is not a verified adult, and an under-threshold
  registration with no guardian workflow configured produces a `restricted`
  account that may read but not write — rather than pretending a workflow
  exists because a checkbox does.
* No response ever contains a pseud's `account_id`; the owner is loaded for
  authorization and then dropped.
* Login and password reset are indistinguishable for an unknown address,
  including in timing (a dummy hash is verified when there is no account).

### Milestone 2 — the pages

A session store that distinguishes "the server says there is no session" from
"we could not ask", so a network blip does not sign anybody out. Registration,
sign in, password reset, the account page (sessions, reading preferences, account
privacy) and the pseud page (create, edit, switch, per-pseud privacy) all talk to
the endpoints above and show nothing that did not come from the server.

Two things are worth remembering from writing them:

* The privacy forms render the key schema the server sends, rather than keeping
  their own list of keys and values. A key added on the server appears in the
  interface without a frontend change, and a key removed stops being offered.
* The reading-preferences form reports the policy ceiling and the *effective*
  rating next to the choice. A preference above the ceiling is remembered and
  says plainly that it will not change what is shown, rather than appearing to
  have worked.

## Bugs found by testing, not by reading

Every one of these was caught by an automated test or a real browser session.

1. **The rate limiter was inert in production.** `axum::serve` was given the
   router directly, so no peer address was ever available; the limiter had no
   key and skipped enforcement. Fixed by serving
   `into_make_service_with_connect_info`, *and* by making the limiter fall back
   to a shared bucket when no address can be determined — so the failure mode is
   "everyone shares one allowance" rather than "nobody is limited".
2. **`AgeState::Restricted` was not a minor state.** A restricted account is by
   construction below the age threshold, so it was silently receiving the adult
   defaults for messaging and taste learning.
3. **The class marker sat inside the limiter.** The fail-closed guard rejected
   every request on every route, because middleware runs outermost-first and the
   class was attached after the limiter rather than before it.
4. **A zero refill rate panicked.** `Duration::from_secs_f64` was handed
   infinity on the way to a retry hint.
5. **The appearance selector applied but never persisted.** `bind:value`
   combined with `onchange` left persistence dependent on listener ordering. A
   unit test on the storage module could not see it; a shell-level test can.
6. **The build identity was frozen.** `build.rs` cached the git revision, so a
   deployed binary would keep reporting the commit it was first built from.
7. **The shell kept claiming a session after a password reset.** Redeeming a
   reset token revokes every session on the account — but the header still said
   "Writing as @quill", because nothing told the session store. Found by driving
   the flow in a browser, and now pinned by a test.
8. **A failed sign-out threw.** The store cleared local state and then re-threw
   the network error, which the caller could do nothing with. It now records the
   failure instead, so the page can say the session may still be live.

## Open risks and known gaps

1. **PostgreSQL has never been executed.** Every PostgreSQL statement is
   written but unverified; there is no server on this machine. A CI job exists
   and fails loudly rather than skipping, but it has never run. This is the
   largest open risk in the project. See ADR 0004.
2. **Template type-checking is not part of the gate.** `svelte-check` cannot
   start in this checkout — it reports "No Svelte configuration found in vite
   config" for every component, including ones that predate this session. The
   Vite build (which compiles every template) and Vitest are what actually
   protect the frontend, so a prop of the wrong shape would not be caught.
3. **The new pages have no automated browser coverage.** They were driven by
   hand through the whole journey; Vitest covers the store, the router, the API
   client and two pages. A Playwright suite is still missing (spec §23).
4. **No email transport.** Password reset returns the token in the response
   outside production and logs only the request inside it — honest, but not a
   shipped flow. SMTP is spec §2.2 optional infrastructure, not yet chosen.
5. **No common-password list.** Password strength is length plus the rate
   limiter, and this is stated rather than dressed up.
6. **"Every route declares a class" is a convention, not a boot-time check.**
   axum does not expose the route table, so the enforcer's fail-closed behaviour
   is unit-tested directly and the end-to-end property is tested for classified
   subtrees. A boot-time audit would need a declared route inventory — which
   spec §24 asks for anyway, and which is the natural way to close this.
7. **Milestone 1 is incomplete against its own list**: no combobox, and the
   richer work-card variants are missing. Layout at 320 px and at 200 % zoom has
   never been measured.
8. **Fonts are not self-hosted.** The intended typography appears only where
   the named families happen to be installed.
9. **`lorehaven migrate | head` panics on a broken pipe.** Cosmetic, but a
   wart; fixing it needs `unsafe` for `SIGPIPE` and the workspace forbids that.
