## The bulk-export stub, third pass

The `ALL_KINDS` fix landed as `kind_index()` (exhaustive `match`, so a variant
without an index fails to compile — verified) plus `ALL_KINDS`, an index-uniqueness
test and a `parse` round-trip test. The compile-forced half is real. The
completeness half is not: the test iterates `ALL_KINDS` and sizes `seen` with a
literal `[false; 10]`, so a variant appended with index 10 and omitted from the
list passes it — mirrored both ways
(`A) [false; 10] -> PASSED — the guard did not notice NewKind`, `B) [false; 11] ->
FAILED`). The guard therefore depends on a hand-maintained literal, which is the
step it was meant to remove; `std::mem::variant_count` is unstable on rustc 1.98,
so the fix is one macro emitting the enum and the list together, or a derive crate.
The same file also still has the older six-kind hand list in
`states_and_kinds_round_trip_through_their_columns`.

Scoped gate for the two crates touched: 31 targets, 763 passed / 0 failed / 0
ignored, one warning (the other workstream's `items`), `test_exit=0`.
