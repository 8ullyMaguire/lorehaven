## 4. What remains and where the next decision point is

### M26 — TTS audio generation (BLOCKED on design decision)
The narration edition infrastructure is complete (create, list, get, machine-producer credited, draft state). What is missing is the actual audio bytes — the call to a TTS engine. Three options:

1. **Local engine** (Coqui TTS, Piper) — self-hosted, no API key, heavy binary dependency on instances.
2. **Cloud provider** (ElevenLabs, AWS Polly) — API key per instance, budget guards, egress costs, privacy posture.
3. **Pluggable** — a `TtsEngine` trait with local + cloud implementations, chosen per instance via config.

This is a multi-day build either way, and the choice of engine affects the whole worker design. The user has not yet decided between local, cloud, or pluggable.

### M26 — Gallery mechanics (not blocked, large)

### Judgement calls

- Transcode targets MP4 (libx264/aac, `+faststart`) because a media work
  is served progressively by a browser; OCR's media type is
  `text/plain; charset=utf-8`.
- `CONVERTER_UNAVAILABLE` is 422. §3.3 lists the code without a status;
  422 says "this instance cannot produce that", which is the truth, and
  503 would suggest waiting.
- A machine-produced derivative's failure is *fatal* (a missing program
  or an input the program refused does not improve on retry); document
  renditions stay transient.
- Expiry is recorded as `expired_at` (a transition) rather than derived
  at read time, because "when did this end" cannot be read off a clock
  comparison.
- The dashboard bands reader-facing counts at 5 (the public aggregate's
  order) and reports them as strings, since a JSON number is what a
  client renders as an exact figure; the author's own work/chapter/word
  counts stay exact.
- The canon/space cursor carries `position|created_at|id` and the limit
  is capped at 200, matching the media list door.
- The leaked-database sweep uses liveness rather than age: `pg_database`
  has no creation timestamp and the name cannot carry one.
