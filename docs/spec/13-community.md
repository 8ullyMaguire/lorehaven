# 13. Community

**Status:** reserved
**Milestone:** M12
**Source:** the corresponding section of the Darkhold specification

## 13.1 The forum

Categories → topics → posts. A topic has an **immutable slug**; the canonical URL is
`/forum/board/{slug}.{id}` and the legacy form still resolves. Read state per topic, follows,
search with snippets, soft delete with curator hard-delete, edit windows with a curator review
queue for non-authors, polls, reactions, topic tags, groups, rooms and DMs.

## 13.2 Work discussion modes

- **`thread_only`** (the default for new works) — the work page carries a typed-vote reaction bar;
  all text discussion lives in the linked forum thread.
- **`comments_only`** — legacy, supported indefinitely.
- **`both`** — supported, operator-warned.

## 13.3 Requests, bounties, prompts

- **A request** is a prompt board. Answers are *works* — an in-archive work, a pasted URL (which
  ingests on acceptance), or a work someone else imported.
- **A bounty** is a sized request with a reward. Bounty size buys **fulfilment priority**, never
  weight, never rank (N-1).
- **A prompt** (a challenge) is the reverse: a writer is given a constraint.

## 13.4 Collections, series, shelves

A **series** is an ordered set of works with a position. A **collection** is a curated bundle with
a blurb and a position, public or private, and a first-class queryable entity. A **shelf** is a
reader's private grouping of bookmarks.

## 13.5 Messaging, groups, spaces

Direct messages are stored, not relayed. A **group** has roles. A **fandom space** is a
sub-community scoped to a canon.

## 13.6 Notifications and feeds

Notifications are generated by domain events and routed by per-domain preferences and routes. Push
subscriptions are per-device and revocable. **Feeds:** Atom for new arrivals, per-work,
per-follow, per-saved-search, per-tag, **per-channel** and **per-mood**. Every feed is a query, not
a fixed list, and every feed has a revocable token.
