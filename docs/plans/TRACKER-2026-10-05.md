## The two failures in this session that were NOT product bugs

Recorded because both were reported as failing suites and both cost real time.

**`/dev/shm` exhaustion is one fault wearing three masks.** `Connection reset by peer`,
`out of shared memory (53200)`, and `could not resize shared memory segment … No space
left on device` appeared in one run and read as three unrelated problems. Cause: Docker's
default 64 MB container shm, against a 32 MB-per-backend segment request from parallel
`CREATE DATABASE`/`migrate`/`TEMPLATE` waves. `ShmSize` is fixed at **create** time, so
`docker start` can never fix it — `scripts/pg-test-db.sh` recreates the container with
`--shm-size 4g` and is now the documented way to provision it. Lowering `--test-threads`
was the wrong fix and it still failed anyway, in `milestone_39`.

**A mutation script patching `discovery.rs` in place poisons concurrent builds.** The
"flake" in `surprise_me` — failing at 8 threads, green alone — was a background
`cargo test --workspace` compiling the tree while the mutation loop rewrote the file
under it. The assertion was correct against the committed source. **Rule: before believing
any flake, run `pgrep -af 'mut-|cargo test'` and `git status --short`.** A mutation loop
must work on a copy or take an exclusive lock.
