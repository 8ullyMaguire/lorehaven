## Closed today, each proved by breaking it

### `snapshot_anonymisation` — five stacked faults, 0/10 → 10/10

The suite had **never been green on any engine**. Each fault was invisible until the
one before it was cleared.

1. **Five subprocess sites hardcoded `127.0.0.1` / `5432` / user `postgres`** while
   `pg_password()` parsed the credential out of `LOREHAVEN_TEST_PG_URL` thirty lines
   away. The credential came from the environment and the endpoint did not, so the suite
   could only pass on a host serving PostgreSQL on the default port. All now route
   through `pg_endpoint()` / `pg_scoped_url()` — one parse of one variable.
2. **`pg_endpoint()` split the URL without stripping the scheme.** `rsplit_once('@')` on
   `postgres://lorehaven:pw@host/db` yields username `postgres://lorehaven`, and
   `pg_dump` reported `password authentication failed for user "postgres://lorehaven"` —
   a credential-shaped error for a string-parsing fault. `pg_password()` was accidentally
   right because it keeps only the part after the colon.
3. **The migration parser merged two definitions of `mutes`.** `0001_identity.sql` creates
   it `(id, pseud_id, target_type, target_id, …)`; `0013_community.sql` drops and
   recreates it as `(muter, muted, until, created_at)`. The union carried four phantom
   columns and emitted `SELECT "id" FROM public.mutes` — a column that has never existed.
   `CREATE TABLE` now replaces; `ADD COLUMN` still merges.
4. **`ctype` was matched against the wrong spelling.** The generator tested
   `("timestamptz","timestamp","date")`, but `information_schema` spells it
   `timestamp with time zone`. So the **live** path — the one production uses — never
   matched, every timestamp column took the TEXT branch, and its regex guard does not
   exist for a timestamp:
   `operator does not exist: timestamp with time zone ~ unknown`. Inverted confidence:
   the lossy fallback path was the correct one.
5. **Client `pg_dump` 18.6 against server 15.19.** 17+ emits `SET transaction_timeout`,
   which aborts the restore under `ON_ERROR_STOP` and was reported as *"the dump does not
   restore into an empty database"* — a claim about the artefact when the fault is the
   toolchain pairing. Unknown GUCs are now filtered by probing the server
   (`current_setting(name, true) IS NOT NULL`) rather than a hardcoded version list.

Plus the restore/`doctor` wiring: `pg_scoped_url("restored")` passed a **literal** where
the `lh_snapshot_doctor_restore_<pid>` variable belonged, so `doctor` was aimed at a
database that had never existed — reported as the self-contradictory *"doctor FAILS
against a snapshot that restored cleanly"*. Both halves were true, and that
contradiction was the tell.

**Three of these five were introduced by me while fixing the others** — a missing `-p`, a
missing `-d`, and the literal-for-variable. All three are the same shape: hand-editing
call sites instead of routing every one through the single parser they were meant to
share. The check that catches all three is running the helper's own query by hand before
wiring it into a 90-second suite. I did that for the last one and it paid off; I skipped
it for the first two and paid twice.

### Two races in the shared scratch-database harness

`reader_surface_t1.rs` and `continue_reading_t1.rs` are **byte-identical from line 60 to
line 125** — a copy-pasted harness — and both hardcode the same database `lorehaven_rs1`.

1. **`pg_database_datname_index`.** A `SELECT 1 FROM pg_database` guard before
   `CREATE DATABASE` is check-then-create, and PostgreSQL has no `IF NOT EXISTS` for it.
   Two threads both see "absent", both issue the statement, and the loser gets the
   duplicate-key error — which is the *outcome*, not a fault: the database now exists.
   Now attempted, then re-checked on error, and the re-check **asserts** so a genuine
   failure still surfaces.
2. **`pg_extension_name_index`, one layer deeper.** Migration 0092 runs
   `CREATE EXTENSION IF NOT EXISTS pgcrypto`; extensions are **database**-scoped while
   these test schemas are not, so 8 parallel migrators reach 0092 together and all
   genuinely try to create it. `IF NOT EXISTS` does not serialise its own existence
   check. Migrators are now serialised by a process-local mutex, matching the actual
   scope of the collision (these suites share a database between *threads*; two processes
   is a different problem with a different owner). Retry was rejected — it re-runs every
   DDL statement in the file for a failure that already left the schema correct.

Verified at **8 threads**, the level that reproduced both, twice. `--test-threads=1`
hides them without fixing them.

## Log hygiene, learned the hard way

Twice today a `/tmp/*.log` file outlived the run that produced it and I nearly reported
it as current — once reporting a `Killed` line that was my own `pkill`, once reporting
the previous run's SQLite totals. Two habits that catch it: compare the log's mtime
against `date`, and write to a **new** filename per run rather than truncating the one
being read.
